A real-time firefighter tracking and alert system that helps incident commanders locate firefighters and mark victims and hazards inside buildings.

EMBER

HARDWAREEMBEDDEDCIOT

EMBER (Emergency Monitor for Building Evacuation and Rescue) is a real-time firefighter tracking and alert system designed for emergency response inside buildings, where GPS becomes unreliable or unavailable.

Each firefighter wears a sensor node built with an Arduino Nano, GPS, IMU, and NRF24L01 wireless radio. The system continuously transmits heading, position, and battery data to a central base station. When GPS is unavailable indoors, EMBER uses IMU-based dead reckoning, combining compass heading and step detection to estimate movement.

Firefighters can also use dedicated buttons to report a victim, mark a cleared room, or flag a dangerous area. These alerts are transmitted to a browser-based command dashboard, where an incident commander can see firefighter locations on a floor plan and monitor reported hazards in real time.

My work spanned the hardware and software integration of the system, including the overall architecture, browser dashboard, Web Serial communication, microcontroller configuration, and the serial JSON protocol connecting the base station to the dashboard.

Motion Data Privacy in XR

RESEARCH SECURITY PRIVACY XR

“SoK: Motion Data Privacy in Extended Reality” is a systematic study of privacy risks associated with motion and behavioral data collected by Extended Reality (XR) systems.

We analyzed 134 research papers to examine the types of motion data collected and studied, the privacy risks they introduce, existing attacks and defenses, and gaps in current research.

My contribution focused on reviewing and analyzing existing research, examining different motion-data modalities and privacy threats, and helping organize the current state of research in XR privacy and security.

Multi-sensor data logger

HARDWAREEMBEDDEDCKICAD

A logger built to sit outside for weeks at a time and record temperature, humidity, pressure, light and two analogue channels to an SD card.

I designed the board in KiCad, wrote the firmware in C, and spent a lot of the project on power: sleep scheduling, sensor duty cycling, and measuring where the current was actually going.

The final build ran 21 days on a single pack, up from four days in the first revision.

16-bit CPU on FPGA

HARDWAREVERILOGARCHITECTURE

A five-stage pipelined processor with its own instruction set, built from scratch in Verilog and synthesised onto an FPGA.

Alongside the hardware I wrote a small assembler in Python so programs could be written in something more pleasant than hex, plus a testbench suite that checks each instruction against an expected register trace.

Hazard handling was the real lesson here — the forwarding logic took three rewrites before the pipeline behaved.

Flight control dashboard

SOFTWAREPYTHONFASTAPIDATA

A dashboard that takes a telemetry stream and turns it into something a person can read while the vehicle is still in the air: attitude, battery, link quality and sensor health, all updating live.

Built with FastAPI and websockets on the backend, with a plain JavaScript frontend so it runs on a laptop in the field with no build step.

It also records every session to disk, so a flight can be replayed frame by frame afterwards.
